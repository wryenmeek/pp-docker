# Deterministic Token Spend Telemetry and Pre-Merge Verification Gates

## Problem
In multi-agent autonomous engineering pipelines, multiple agent conversations and subagents contribute commits to branches and pull requests. Without cryptographically deterministic session receipts embedded in git history:
1. Multi-turn token expenditure cannot be accurately audited or mapped back to specific features, bug fixes, or agents.
2. In-memory agent contexts and prompt cache hit rates (>90% cache efficiency) were obscured, leading to 3x-4x cost distortion if billed tokens are computed as flat input tokens.
3. Code could be merged into `main` before spend reports were generated or before all committed agent sessions were verified.

## Symptoms
- Commits generated by autonomous agent tooling lacked verifiable session provenance.
- PRs were merged without visibility into actual agent token consumption, model distributions, or execution times.
- Telemetry scripts produced inaccurate costs by omitting prompt caching pricing tiers (`Uncached + 0.25 * Cached + Output`).
- Hook interception regexes inadvertently matched inline script strings or greps containing merge commands, creating false-positive denials.

## What Didn't Work
- Relying on manual developer discipline to append session IDs to commit messages: agents and engineers frequently omitted trailers under rapid iteration.
- Loose regex matching (`re.search(r"\bgh\s+pr\s+merge\b", cmd_line)`) in harness hooks: any command that printed, grepped, or wrote unit test files referencing `gh pr merge` was erroneously intercepted and blocked.
- Querying unpaginated GitHub commit lists: PRs with >100 commits truncated commit history and produced incomplete session coverage calculations.
- Flat token pricing models: Treating multi-turn conversation caching as full-rate input tokens vastly overestimated actual spend.

## Solution
1. **Deterministic Commit Receipts via PreToolUse Hook:**
   - The Antigravity lifecycle hook intercepts `run_command` invocations containing `git commit`.
   - If the active session ID is absent from the commit message, the hook automatically injects the git trailer:
     ```
     Antigravity-Session-ID: <session-conversation-uuid>
     ```
2. **Fail-Closed Pre-Merge Verification Gate:**
   - Pre-merge hook checks intercept `gh pr merge` and `git merge` commands before execution.
   - PR telemetry is verified using `antigravity-telemetry verify --pr <PR_NUM>`.
   - The verification gate inspects 100% of commits (paginated via GraphQL for large PRs) and ensures that all committed Antigravity session IDs are accounted for in a verified PR telemetry comment.
3. **Prompt Cache Economics Formulation:**
   - Unified telemetry calculates multi-turn cache economics deterministically:
     $$\text{Billed Tokens} = \text{Input}_{\text{uncached}} + 0.25 \times \text{Input}_{\text{cached}} + \text{Output}$$
   - Published comments include total tokens, cache hit rate percentages, breakdown by model family (Pro vs Flash), and estimated billed cost.
4. **Command Boundary Hook Matching:**
   - Hook regexes enforce strict command boundaries (`(?:^|[;&|]\s*)`) to prevent self-interception during file generation or grepping.

## Why This Works
- Git trailers are standard, machine-readable metadata preserved across git rebases, cherries, and merges.
- Harness-level injection guarantees 100% compliance without requiring agent models to reliably remember formatting instructions.
- Fail-closed verification prevents unverified merges while allowing override flags (`--skip-telemetry` or emergency manual flags) when justified.

## Prevention
- All agent commits must carry `Antigravity-Session-ID`.
- Before merging any pull request, execute:
  ```bash
  antigravity-telemetry post --pr <PR_NUM>
  ```
- Keep unit tests covering CLI hooks with mock command lines exercising prefix separators (`;`, `&&`, `||`, `|`) and inline code strings.
